# Proposal｜MVP 核心配置功能

## Why

使用者目前需自行比較收納商品尺寸及排列，缺少能對照既有空間的互動工具。本次建立 F01～F06 的最小可操作流程，供後續驗證配置決策負擔與尺寸判定品質；尚未宣稱產品價值已獲驗證。

## What Changes

- **F01**：設定空間寬（左右）、深（前後）、高三軸尺寸，以公分、1～999 的正整數為限制；離開欄位或按「套用空間」時檢查，無效時保留上一次有效空間。
- **F02**：載入 `product-info/shuter-products.json` 的樹德 23 筆商品，呈現商品圖片、品牌、名稱、寬／深／高、單位、來源與尺寸備註，保留原始小數；畫面註明本專案為課程作業練習。
- **F03**：以固定寬、深方向放入、移動及移除多件商品，同一商品可建立不同配置實例；本次不可旋轉。空間與配置保存在瀏覽器本機，重新整理後仍保留。
- **F04～F05**：新增、移動或移除後自動檢查尺寸、四側越界、重疊與高度，邊緣貼齊合法。
- **F06**：異常只提示、不阻擋；位置及配置保留，但任何已知違規均不得顯示「符合全部限制」。
- AC01～AC08 均為本次驗收依據；AC07、AC08 的細節已於 2026-11-09 審查時由使用者決定，見下方「審查決策」。

## Capabilities

### New Capabilities

- `space-settings`：空間尺寸輸入、單位、檢查時機與有效設定。
- `product-catalog`：單一品牌真實商品目錄、圖片、來源、尺寸備註與作業練習聲明。
- `layout-editing`：固定方向的 2D 放入、移動、移除、多實例、自由配置與本機保存。
- `layout-validation`：尺寸、邊界、碰撞、高度檢查、即時整體判定與異常明細。

### Modified Capabilities

無。`openspec list --specs --json` 顯示目前沒有正式 capability。

## Impact

提案建立時，專案尚無 `package.json`、應用程式或測試；本次新建純前端 React／Vite／TypeScript 專案，依專案設定採 npm、React Router、Tailwind CSS、Zod、Playwright、ESLint 與 Prettier。不新增後端、API 或資料庫；商品 JSON 為既有輸入，不重抓、不改尺寸。

## 範圍外

- `sdd-input.md` 3.2 的跨品牌、即時商品 API、自動搜尋／篩選／推薦、最佳配置、自訂商品、3D、輸出、價格庫存、購買與採購功能。
- 商品旋轉、堆疊／摺疊狀態切換、特殊形狀幾何；`stackable` 不衍生新功能。
- 本次不規劃分析事件平台或 8 人價值比較的實際執行；40 筆品質案例納入驗證規劃，不虛構結果。
- 「全部清空」的重設按鈕、跨裝置同步與帳號；配置只保存在使用者自己的瀏覽器。

## 審查決策（2026-11-09）

AI 初稿把下列問題列為待釐清；使用者審查後決定如下。原始選項與取捨保留在 commit `966da3f` 的初稿中。

| 編號 | 問題 | 使用者決定 | 理由 | 影響的規格 |
|---|---|---|---|---|
| Q07-1 | 何時顯示無效輸入提示 | 離開欄位或按「套用空間」時 | 打字中不會一直跳出錯誤 | space-settings、E2E-003、E2E-014 |
| Q07-2 | 已有配置後輸入無效值 | 保留上一次有效空間，並標示「仍使用上一次的有效空間」 | 畫面與配置不會突然消失 | space-settings、E2E-014 |
| Q07-3 | 數值範圍與格式 | 1～999 的整數，只能由數字組成（前後空白忽略）；小數、負號、科學記號一律無效，不自動截斷 | 設上限可控制配置區比例 | space-settings、E2E-003 |
| Q08-1 | 多種異常如何顯示 | 同時列出全部異常 | 最直接，使用者一次看到所有問題 | layout-validation、E2E-015 |
| Q08-2 | 異常如何定位 | 有問題的商品在配置區變色標示，並在明細逐項列出；重疊列出相關的兩件商品；依放入順序排列 | 使用者知道要移哪一件 | layout-validation、E2E-015 |
| Q08-3 | 部分解除時的回饋 | 已解除的異常從明細移除，剩餘的保留 | 明細永遠反映目前狀態 | layout-validation、E2E-013、E2E-015 |
| 追加 1 | 移除已放入的商品 | 要做，每件商品可單獨移除 | 放錯時需要能拿掉，否則只能拖到旁邊 | layout-editing、E2E-016 |
| 追加 2 | 商品圖片 | 顯示官網圖片，載入失敗時顯示替代圖示；畫面與 README 註明「課程作業練習，商品資料與圖片版權屬樹德」 | 只看名稱難以辨識商品 | product-catalog、E2E-017 |
| 追加 3 | 重新整理後是否保留配置 | 保留，存在瀏覽器本機 | 誤觸重新整理時，排很久的配置不會消失 | layout-editing、E2E-018 |
| 追加 4 | 空間軸名稱 | 空間與商品統一使用寬（左右）、深（前後）、高 | 原稿空間用「長、寬」對應商品「寬、深」，容易混淆 | 全部 specs、design D03、E2E |

**上游需求變更紀錄**：`sdd-input.md` F01 寫「長、寬、高」，本次改為「寬、深、高」，只改名稱、不改行為；`sdd-input.md` 原文保留不覆寫。

## 待釐清問題

- 商品內外尺寸不明時，目前沿用資料備註並提示「依所列尺寸檢查」，不刪減 23 筆。若之後要補證或排除特定商品，需另開變更。
- 官網圖片是否允許長期引用，本次未查證；作業練習期間以聲明處理。

### 套件管理調整

使用者於本次實作階段指示改用已安裝的 npm，取代初稿的 pnpm；同步專案設定、設計、任務與測試命令，使用 package-lock.json。產品行為與驗收條件不變；舊設定保留於 Git 歷史。
