# E2E Testing Checklist｜MVP 核心功能

> **狀態：測試計畫，尚未執行。** 實作後由 Playwright MCP 操作並留證；只有實際驗證通過才能勾選。AC07、AC08 額外顯示行為仍是草案，不視為已核准驗收門檻。

## Test Setup

- **Start URL / route：** 路由 `/`；實際 origin **TBD**，實作後使用終端機顯示的 Vite 位址，不假設連接埠。
- **Viewport：** 桌面 1440 × 900，Chromium。此為本輪執行條件，不新增手機版產品驗收承諾。
- **Test data / accounts：** 不需帳號。唯一目錄為 `product-info/shuter-products.json`，23 筆；不攔截／替換成假商品。KD-2619（以下簡稱 K）38 × 19 × 26；DB-26（D）51.7 × 37.05 × 18.55，單位 cm。
- **Prerequisites：** 應用程式已實作、依 README 安裝依賴與啟動（預計 `pnpm install`、`pnpm dev`，目前尚不存在）；確認起始頁可載入。沒有後端／資料庫／seed／登入依賴。
- **UI 契約：** 目前沒有現成 selector。下列名稱來自 design.md D03／D06 的新介面設計；實作後若有變動，先同步文件。欄位「長（左右，cm）」「寬（前後，cm）」「高（cm）」、按鈕「套用空間」「放入配置」、圖面「收納配置區」、結果「配置檢查結果」。商品動作需限定在指定商品的可見卡片內，避免同名按鈕歧義。
- **隔離：** 每案使用全新瀏覽器 context 開啟 `/`，確認沒有既有 placements；不假設重新整理會清空配置，不要求新增重設功能。結束關閉該 context。
- **座標：** 以可見空間邊框左上角為 (0,0)，x 向右、y 向後。拖曳使用圖面與商品可見矩形的 bounding box、顯示比例及游標抓取偏移換算，不讀 React store、不從 console 注入 placements。一般案例選擇有明顯餘裕的位置；精確到 0.01 cm 的案例由下方 QA fixtures 驗證。
- **外部依賴：** 檢查來源連結的 href 是否符合 JSON 即可，不需官網在線或下單。圖片尚未核准，不將圖片網路請求或圖片顯示列為通過條件。
- **Evidence：** 實作後將各案指定截圖、可見文字與必要紀錄存於本 change 的 `evidence/`，以 case ID 命名；本階段不建立假證據。記錄 console error 及失敗的應用程式資源請求。

## 1. 空間與目錄

- [ ] E2E-001 初始狀態不得假稱符合

  - **操作：**
    1. 開啟 `/`，查看三軸欄位、方向／公分說明與「配置檢查結果」。
  - **預期結果：** 尚無有效空間，不出現成功的「依所列尺寸，符合全部限制」判定；不要求特定空配置文案。
  - **證據：** 初始畫面截圖與結果文字，記錄啟動相關 console／network 錯誤。
  - **清理：** 關閉 context。

- [ ] E2E-002 設定正整數空間
  - **優先級：** High
  - **前置條件：** 全新 context。
  - **操作：**

  - **清理：** 關閉 context。

- [ ] E2E-003 非正整數不被接受為有效空間
  - **優先級：** Critical

## 2. 放入、移動與固定方向

- [ ] E2E-006 正常放入與移動自動檢查

- [ ] E2E-007 同款多件獨立移動與重疊修正
  - **優先級：** Critical
  - **前置條件：** 全新 context，套用 100 × 80 × 40。
  - **操作：**
    1. 放入 K，移至約 (10,10)；記錄第一件位置，再放入第二件 K。

  - **證據：** 重疊與解除後各一張截圖、商品數量、第一件位置與結果文字。
  - **清理：** 關閉 context。

- [ ] E2E-008 不可旋轉及平面尺寸超限

    1. 放入 K，觀察圖面方向與檢查結果。

  - **證據：** 商品、邊界、控制及不符合結果截圖。
  - **清理：** 關閉 context。

- [ ] E2E-009 小數尺寸在配置中不取整
