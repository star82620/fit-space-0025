# Proposal｜商品手動旋轉 90 度（change 2）

## Why

目前每件商品只能依官網寬、深方向擺放；使用者即使想比較另一個平面方向，也無法自行切換。本次讓使用者逐件手動旋轉，保留既有自由配置與嚴格尺寸判定原則。

## What Changes

- 每件已放入商品提供「旋轉」按鈕；每按一次在原方向與轉 90 度之間切換。轉向時只交換平面寬、深，高度與原商品資料不變。
- 旋轉固定商品左上角座標，不自動移位；越界或重疊照現行規則提示、保留位置，整體不得誤標為符合。
- 旋轉後立即重新檢查，旋轉狀態與空間、位置一同保存在瀏覽器本機，重新整理後還原。
- 系統不自動旋轉，也不建議方向。既有 40 筆固定品質案例保持原樣，另增旋轉專用固定案例與 Playwright MCP 瀏覽器清單。

### 既有決策變更與影響

封存的 [change 1 提案](../archive/2026-11-09-build-mvp-core/proposal.md) 依當時決策把商品旋轉列為範圍外，現行 `layout-editing` 的「固定商品寬深方向」也明定禁止旋轉。**本次使用者明確改為允許逐件手動切換 90 度**；理由是讓同一件商品能比較兩種平面擺法。舊決策與 `sdd-input.md` 均保留，不覆寫歷史。

| 受影響規格 | 變更 |
| --- | --- |
| `layout-editing`：固定商品寬深方向 | 由禁止旋轉改為放入時維持原方向、使用者可逐件切換；左上角固定，不自動轉向 |
| `layout-editing`：配置保存在瀏覽器本機 | 旋轉狀態隨實例保存與還原；舊版無旋轉欄位的配置視為原方向 |
| `layout-validation`：固定方向的三軸尺寸檢查 | 寬、深依實例當前方向比較，高度仍取原值 |
| `layout-validation`：配置異動自動更新 | 旋轉加入即時重檢觸發；既有邊界、重疊與整體判定規則套用轉向後矩形 |

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `layout-editing`：修改「固定商品寬深方向」與「配置保存在瀏覽器本機」；保留原需求的完整既有情境並增列旋轉情境。
- `layout-validation`：修改「固定方向的三軸尺寸檢查」與「配置異動自動更新」；旋轉後以目前平面尺寸重檢。

## Impact

影響 `Placement` 實例狀態、reducer、`localStorage` 驗證與恢復、SVG 畫布／實例控制、純幾何檢查及其測試；沿用現有 React、TypeScript、Zod、Playwright 與 npm。商品 JSON、空間輸入規則、資料來源與既有 40 筆固定品質案例保持不變。不新增後端、API 或資料庫。

## 範圍外

- 任意角度、多次累加角度、繞中心旋轉、3D 翻轉或高度方向切換。
- 系統自動旋轉、推薦方向、最佳排列、吸附或自動移位。
- 修改商品 JSON 尺寸、舊 40 筆品質案例或既有空間尺寸規則。

## 待釐清問題

無。舊版本機保存資料沒有旋轉欄位時預設原方向，是為保留既有配置的相容處理；本次不增加使用者選項。
